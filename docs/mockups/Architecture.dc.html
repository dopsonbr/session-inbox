1 · Event in
  • Hooks: Notification (needs input), PreToolUse (permission), Stop (ready to review / failed), SubagentStop, SessionStart.
  • Each hook pipes its JSON to the service: session_id, cwd, transcript path, tool and input.
  • The tree comes from cwd → project, session_id → session, subagent events → children.
  • Progress events update state quietly and never notify.
2 · Answer or approve
  • Approvals: PreToolUse holds the call and long-polls the service, then returns allow or deny. On timeout it falls back to the normal prompt in Claude.
  • Questions: the answers form sends one reply through the outbox → claude --resume.
  • Reply only when the session is idle or waiting, so you never have two writers.
  • The outbox uses idempotency keys and marks each reply delivered or failed.
3 · Notify and hand off
  • Tauri posts the notification. A click or action routes to sessioninbox://item/<id>.
  • Open in Claude: cloud sessions link to claude.ai/code/…; desktop sessions use the Claude app's URL scheme (the spike decides if this can be exact-session).
  • Menu bar badge = count needing you; pause and snooze live there.
  • Quiet hours, plus a per-project mute.
