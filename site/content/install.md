# Install

Session Inbox installs with one command on Apple silicon Macs. You need macOS and either the Claude desktop app or the `claude` CLI. You don't need Bun or Rust. Intel Macs install [from source](#install-from-source).

## One-line install

```bash
curl -fsSL https://raw.githubusercontent.com/dopsonbr/session-inbox/main/install.sh | sh
```

The script downloads the latest [GitHub release](https://github.com/dopsonbr/session-inbox/releases) (about 125 MB: three compiled binaries and the menu-bar app), checks its SHA-256, and runs the `session-inbox install` command bundled inside it. Nothing needs `sudo`. If you'd rather read the script first, it is [`install.sh`](https://github.com/dopsonbr/session-inbox/blob/main/install.sh) at the root of the repository.

You can run it again at any time. It replaces the binaries, doesn't duplicate the hooks, and repairs a broken install.

To install a specific version instead of the latest, set `SESSION_INBOX_VERSION`. The `v` is optional:

```bash
curl -fsSL https://raw.githubusercontent.com/dopsonbr/session-inbox/main/install.sh | SESSION_INBOX_VERSION=v0.2.0 sh
```

Options for the installer go after `sh -s --`. For example, to skip the menu-bar app:

```bash
curl -fsSL https://raw.githubusercontent.com/dopsonbr/session-inbox/main/install.sh | sh -s -- --no-app
```

## What to do after installing

1. **Click Allow when macOS asks about notifications.** The menu-bar app asks the first time it starts. If you miss the prompt, or the app restarts before you answer it, macOS records "denied" and never asks again. The fix is in System Settings: Notifications, Session Inbox, Allow. The [Setup check](troubleshooting.md#the-setup-check-in-the-app) links straight there.
2. **Restart any Claude session that's already open.** Claude reads hooks when a session starts. New sessions pick them up on their own.
3. **Run the setup check:**

   ```bash
   session-inbox doctor
   ```

   It tells you what's wrong and how to fix it. The same checks are in the app, on the **Setup check** page. See [Troubleshooting](troubleshooting.md).
4. **Optional: choose the Alerts style.** In System Settings, Notifications, Session Inbox, choose **Alerts**. Banners disappear after a few seconds; Alerts keep Allow and Deny on screen until you answer.

Two things work only with the `claude` CLI logged in: replies to a session that is sitting idle, and titles generated by Claude when the desktop app doesn't supply one. If you only use the desktop app, run `claude` once in a terminal and log in. The desktop app's sign-in isn't shared with the CLI. Without it, the reply box says so and offers **Open in Claude**; everything else works.

## What it changes on your Mac

The installer touches these places and nothing else:

| Where | What |
| --- | --- |
| `~/Library/Application Support/SessionInbox/` | The `inbox-hook`, `inboxd` and `session-inbox` binaries, the UI, `install.json` (how it was installed), the SQLite database, the daemon's socket and token files, and its logs. |
| `~/Library/LaunchAgents/com.sessioninbox.inboxd.plist` | A launchd agent named `com.sessioninbox.inboxd` that keeps the daemon running and starts it at login. |
| `~/.claude/settings.json` | Hooks for Session Inbox are merged in. If the file changes, a backup is made first (`settings.json.bak-<timestamp>` beside it). Everything else in the file is kept, and only entries for `inbox-hook` are ever touched. |
| `~/Applications/Session Inbox.app` | The menu-bar app. It is opened after install and registers itself to start at login the first time it runs. |
| `~/.local/bin/session-inbox` | A symlink to the `session-inbox` command. If `~/.local/bin` isn't on your `PATH`, the installer says so; add it in `~/.zshrc`. |

The installer also clears macOS's quarantine flag on the files it copies, so a tarball downloaded in a browser still runs. The app is signed ad hoc, not with a Developer ID, and it isn't notarized.

Because the hooks live in your user-level Claude settings, they apply to every Claude session on the machine. That is the point, and it is why the hook is built to [fail open](holds.md#fail-open).

## Install from a tarball

You can install on a second Mac before the release is published, or without GitHub, from a tarball built on the first Mac. On the Mac with the checkout, build it (the app is included, so you need Bun and Rust there):

```bash
bun scripts/release.ts
```

It writes `dist/release/session-inbox-<version>-macos-arm64.tar.gz` and a `.sha256` file beside it. Copy the tarball to the other Mac, then unpack it:

```bash
tar -xzf session-inbox-<version>-macos-arm64.tar.gz
```

Run the installer from inside it. Without `--yes` it's a dry run that prints every change, including a diff of your Claude settings:

```bash
./session-inbox-<version>/bin/session-inbox install
```

Then apply it:

```bash
./session-inbox-<version>/bin/session-inbox install --yes
```

Release builds are Apple silicon only, so build and install on Apple silicon Macs.

## Install from source

Use this on Intel Macs, or when you want to work on Session Inbox itself. You need [Bun](https://bun.sh) 1.4 or later, Rust (`brew install rust`) for the menu-bar app, and the Claude desktop app or the `claude` CLI.

```bash
git clone https://github.com/dopsonbr/session-inbox && cd session-inbox
```

```bash
bun install
```

The install script is a dry run by default. It prints every file, launchd and `settings.json` change, including a diff of your Claude settings, and applies nothing:

```bash
bun scripts/install.ts
```

Review the output, then apply it. `--app` also builds the menu-bar app, installs it into `~/Applications` and opens it. The first Rust build takes a few minutes:

```bash
bun scripts/install.ts --yes --app
```

Without `--app` you get the daemon, the hook and the browser UI, but no menu-bar badge or native notifications.

A source install can later switch to the release build with `session-inbox update --yes`. See [Updating](updating.md).

## Try it in one project first

To leave your global Claude settings alone, install the hooks into a single repository and run the daemon in a terminal. This works from a source checkout:

```bash
bun scripts/install.ts --yes --no-launchd --settings /path/to/repo/.claude/settings.local.json
```

```bash
bun apps/daemon/src/main.ts
```

The daemon logs the inbox URL. Press Ctrl-C to stop it. Only sessions started in that repository will report to it.

## Uninstall

`session-inbox uninstall` is a dry run until you add `--yes`. Run it once to see what it would do:

```bash
session-inbox uninstall
```

Then apply it. This removes the hooks (only Session Inbox's own entries), the launchd agent, the `~/.local/bin` link and the app:

```bash
session-inbox uninstall --yes
```

That leaves your data in `~/Library/Application Support/SessionInbox/`. To delete the binaries, database and logs too:

```bash
session-inbox uninstall --yes --purge
```

From a source checkout, `bun scripts/uninstall.ts` takes the same flags, and `--app` removes the app. To undo the hooks by hand, restore the `settings.json.bak-<timestamp>` file the installer left next to your Claude settings, or delete the entries that run `inbox-hook`.
